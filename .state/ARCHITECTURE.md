# Architecture

`docs/` is the product page: a headline, `#quickstart` (Apps, One-liner, npm, Hackable), then the sample. Orbit copies that folder to `public/products/delivery-signal/` for `/products/delivery-signal/` on alextouvras.com. Its install chooser offers Apps, One-liner, npm, and Hackable for macOS & Linux and for Windows. `delivery-signal/install.sh` and `install.ps1` copy the checker onto the machine and add `delivery-signal` or `run`. The root `package.json` exposes the same command for npm. None of those install Python. The page reads a CSV in the browser and runs the same `pipeline.py` and `extract.py` copied into `docs/engine/` by `delivery-signal/assemble_site.py`. The export is not uploaded. GitHub Pages at `https://alextouvras.github.io/delivery-signal/` is the installable address after the repository Pages source is `main` and `/docs`. Install links point at `AlexTouvras/delivery-signal` on `main`.

`delivery-signal/run`, `run.ps1`, and `run.cmd` are the `run` command in bash, PowerShell, and Command Prompt. Each runs `pipeline.py` with `python3`, `python`, or `py` when that binary is already on PATH, and does not install a runtime. `run` with no file opens the configuration page on 127.0.0.1 port 8767. The page saves `.delivery-signal/project.json` with the site and the project key. Jira and Azure DevOps are read from the project for that save; a CSV is shown only for another tracker. `run connect` opens that same page. `run connect jira|ado|other` still writes the project file from a script. `run import` reads a connected Jira or Azure DevOps project even when a CSV path is given. For another tracker, `run import issues.csv` copies the file. `run report` writes the brief from that folder. The token stays in the page for that read, or in `JIRA_EMAIL` and `JIRA_API_TOKEN`, or `ADO_PAT`. `delivery-signal/link.py` does that read over HTTPS and does not store the token. `skills/delivery-signal/SKILL.md` tells an agent in this repo to type that same `run` command in the terminal it already has. `delivery-signal/connect.py` still serves a local page on 127.0.0.1 for a browser on this computer. The form and `POST /run` build a brief from an uploaded CSV and delete the temp file. `GET /sample` opens the Northline brief. `delivery-signal/extract.py` maps a canonical sheet, a Jira CSV, or an Azure DevOps CSV onto one work-item shape. Header aliases cover the columns those products document; `columns.json` overrides a renamed field. `delivery-signal/pipeline.py` applies the same rules to that shape and writes `brief.json`, `brief.md`, `brief.html`, and a dated HTML file to forward. Progress on the pulse counts story points Done for each project, and again for each epic, feature, or initiative from its direct children. Epic, feature, and initiative points stay out of the project total. Remaining and the original estimate are summed where both cells are numbers. An open Highest or High item with an empty story point or effort cell is one finding, and three or more in the same project and priority collapse to one count. Remaining above the original estimate cites both numbers. A Done item whose remaining cell is not zero is cited. A story point or remaining figure that changed since the previous export is on the change list beside items that appeared or closed. Those figures are not turned into days. Jira time-tracking text such as `1d` is copied as written. Azure DevOps reads Original Estimate and Remaining Work beside Effort. The result id is a hash of the finding ids, the set-aside ids, the decisions, the pulse, and the change list, so the three Northline encodings match. Evidence in the HTML starts collapsed. The pay hypothesis and the next cycles are in `delivery-signal/PLAN.md`. Approval stays `pending`.
